# 방문자 기록 및 분석 대시보드 리뉴얼 사양서 (Visitor Logs & Dashboard Renewal)

본 문서는 Lookalike 서비스의 9차 고도화 작업인 **방문자 기록 및 분석 대시보드 리뉴얼** 사양을 정리합니다. 기존 인프라(Elasticsearch 및 Kafka 등)의 복잡성을 완전히 제거하고, 단일 PostgreSQL 중심의 실시간 적재 및 유저 행동 패턴 분석 아키텍처로 개편한 내용을 상세히 수록하고 있습니다.

---

## 1. 아키텍처 개요 (Architecture Overview)

기존 분산 아키텍처에서 발생하던 미들웨어 관리 오버헤드를 줄이고, 렌더(Render) 클라우드 인프라의 무료 티어 리소스 한계(512MB RAM, 1vCPU)를 효과적으로 극복하기 위해 **PostgreSQL 단일 데이터베이스 기반의 초경량 분석 파이프라인**을 구축했습니다.

```
[클라이언트 검색 및 유입]
        │
        ▼ (FastAPI 웹 서버 라우터)
 ┌──────────────────────────────────────────────┐
 │ • 클라이언트 IP 및 User-Agent 추출          │
 │ • DB 및 메모리 기반 OWNER IP 대조          │
 │ • 한국 표준시(KST) 기반 타임스탬프 로깅      │
 └──────────────────────────────────────────────┘
        │
        ▼ (PostgreSQL `search_logs` 테이블 직접 적재)
 ┌──────────────────────────────────────────────┐
 │ • IP 주소, 검색어, 이미지 업로드 여부 보존   │
 │ • `owner_ips` 조인을 통한 세션 유형 구분    │
 └──────────────────────────────────────────────┘
```

## 2. 주요 기능 및 아키텍처 사양 (Key Features & Specifications)

### 2-1. 데이터 실시간 수집 및 적재 (Real-time Ingestion)
- **FastAPI 미들웨어 단일화**: 검색 쿼리 및 이미지 검색 트리거 시, 백엔드 라우터 레벨에서 비동기로 `search_logs` 테이블에 직접 로그를 삽입합니다.
- **한국 표준시(KST) 기준 통일**: 모든 시간 데이터를 보정하여 날짜와 시각 전체(`YYYY-MM-DD HH:mm:ss`)가 KST 기준으로 정밀하게 조회 및 기록되도록 직렬화 체계를 수정했습니다.

### 2-2. 다중 조건 기간 필터링 및 동적 날짜 범위 조회
- **분석 범위 동적 지정**: `오늘(24시간)`, `최근 7일`, `최근 30일` 등 기본 템플릿 필터 외에 **`[직접 입력]`**을 지원하여 사용자 설정 Date Picker 폼을 통해 임의의 날짜 범위를 유동적으로 탐색할 수 있습니다.
- **UI 반응성 개선**: 셀렉트박스 및 기간 필터 영역의 레이아웃 글자 잘림 현상을 방지하기 위해 CSS 너비 스펙을 확장(155px)하여 뷰포트 정렬을 개선했습니다.
- **동적 SQL 최적화**: 시작일과 종료일이 명시될 시 시계열 조건절(`create_dt >= :start_date AND create_dt <= :end_date + 1일 - 1초`)을 바인딩하여 쿼리 타임아웃을 미연에 방지합니다.

### 2-3. 접속 기기 및 방문 경로 경량 분석 (Client & Traffic Analysis)
- **경량 User-Agent Parser**: 외부 무거운 라이브러리 탑재 없이 브라우저 내장 User-Agent 정보를 탐색하여 OS(Windows, macOS, Android, iOS, Linux) 및 브라우저(Chrome, Safari, Firefox, Edge, IE) 유형을 99% 수준으로 정밀 식별합니다.
- **유입 유동 분석**: 단순 검색어 쿼리(`/search?q=`), 이미지 특징 분석 검색(`/search/by-image`), 그리고 메인 페이지 등의 직접 유입 트래픽을 분류하여 주요 검색 및 이동 경로에 대한 점유율 지표를 산출합니다.

### 2-4. 가상 지오 매핑 및 Leaflet.js 시각화 (Geo-mapping)
- **로컬 해시 기반 Geo-mapping**: 외부 위치 측위 API 비용 및 응답 속도 지연(Latency) 문제를 우회하기 위해, 클라이언트 IP의 해시 패턴을 기반으로 국내 주요 광역시 및 통신망(KT, SKB, LGU+, 세종텔레콤 등 ISP) 정보와 매칭하는 초고속 동적 가상 지오 맵핑 아키텍처를 도입했습니다.
- **Leaflet.js 기반 맵 렌더링**: 지도 분석 탭 로딩 시 OpenStreetMap 데이터를 활용하여 접속자들의 지리적 밀집 분포를 마커 핀(Marker Pin) 클러스터 형태로 직관적으로 시각화합니다.

### 2-5. 관리자(OWNER) IP 식별 및 격리 필터
- **통계 이중화 설계**: 대시대시보드 내 트래픽 분석 시 서비스 운영 테스트를 유발하는 관리자의 접속 정보를 별도로 분류(전체 / 일반 사용자 / 관리자 통계)하여 실서비스 이용자의 트래픽 통계를 온전히 격리 분석할 수 있습니다.
- **IP 대역 하드코딩 제거**: 과거 특정 통신사 대역(`220.116.*.*`)을 소스코드 상에 하드코딩하여 식별하던 레거시 구조를 완전 폐기하고, 오직 DB 및 영구 세션 상태 정보를 대조하도록 표준화했습니다.
- **로컬 루프백 필터 완화**: 로컬 개발 시 겪는 `127.0.0.1` 및 `::1` 주소가 제외되던 문제를 수정하여 로컬 접속 환경도 안전하게 관리자 IP 및 접속 이력으로 자동 및 수동 기록되도록 처리했습니다.

## 3. 관련 데이터베이스 테이블 사양 (Database Tables Schema)

방문자 정보 적재 및 관리자 매핑을 위해 사용되는 데이터베이스 구조입니다.

### 3-1. `search_logs` (방문 및 검색 이력 테이블 - 메인 DB)
사용자가 텍스트 혹은 이미지로 검색할 시 실시간 생성되는 데이터입니다.
- `log_id` (PK)
- `ip_address` (접속 IP)
- `user_id` (유저 식별자 - 로그인 시 바인딩)
- `user_agent` (브라우저 정보)
- `input_text` (검색 키워드)
- `thumbnail_url` (이미지 검색 시 업로드 경로)
- `create_dt` (한국 표준시 기준 생성 일시)

### 3-2. `owner_ips` (관리자 IP 정의 테이블 - 메인 DB)
대시보드에서 OWNER 세션으로 필터링하고 제외할 관리자 IP의 목록입니다.
- `ip_address` (PK, 관리자 IP 주소)
- `memo` (식별을 위한 메모 - 예: "Localhost (Auto)", "Parameter-Registered")
- `create_dt` (등록 및 최종 갱신 일시)

## 4. 보안 가이드 및 비공개 조치 (Security Guidelines)

- **보안 접속 경로의 정보 격리**:
  개발 과정에서 관리자 식별을 즉시 자동 갱신 및 등록하기 위해 임시 사용한 **특정 보안 쿼리 매개변수 정보** 및 해당 연동 플래그는 일반 사용자가 볼 수 없도록 비공개로 취급합니다. 본 사양서 및 외부 매뉴얼 상에 해당 매개변수 명칭을 직접 하드코딩하여 노출하지 않아야 하며, 대신 **"인증된 쿼리 스트링 파라미터를 활용한 관리자 IP 즉각 등록 메커니즘"**으로 추상화하여 표현합니다.
