1인 경량화 최적화 성과

서버리스 및 Free Tier 한계 내에서 512MB RAM OOM 문제를 완벽하게 해결하고 아키텍처를 리팩토링한 주요 공적입니다.

한
Single-Handed Refactoring Lead · Full-Stack Architect
한대성
Han Dae-Seong
기존의 고비용 분산 인프라(AWS EC2 xlarge 및 14개 컨테이너)를 **월 운영비 0원(Free Tier)의 극한 효율 서버리스 환경**으로 1인 재구축 완료했습니다. Render 무료 티어의 512MB 램 제약을 극복하기 위해 YOLO 및 Fashion-CLIP 추론 모델을 원격 Hugging Face Space API로 완벽하게 이관(OOM 차단)하였으며, Elasticsearch/Redis/MongoDB 등 3종 데이터베이스 인프라를 **Neon DB (pgvector HNSW)** 하나로 기적처럼 일원화하여 성능과 비용 두 마리 토끼를 모두 잡았습니다.
Serverless Free-Tier (비용 100% 절감) pgvector HNSW 벡터 검색 통합 HuggingFace Space YOLO/CLIP API 이관 cgroups/psutil 경량 모니터링 직접 구현 Render 512MB RAM OOM 방어 Redis 배제 및 DB 기반 세션 전환
✦ 마우스를 올려 리팩토링 성과 세부 내역 확인
🧠 Render Free Tier (512MB RAM) 메모리 최적화
  • OOM(Out Of Memory) 원천 차단 — 대형 로컬 AI 모델(Fashion-CLIP, YOLOv8) 로딩을 제어하는 USE_LOCAL_ML 토글 스위치 설계 및 Gradio API 기반 HF Space 비동기 호출 구현으로 512MB RAM 환경 완벽 이식.
  • 가비지 컬렉션 및 메모리 해제 강화 — 추론이 비활성화되거나 불필요한 라이브러리 임포트를 차단하여 메모리 누수 방지 기믹 완성.
⚡ 데이터베이스 및 데이터 파이프라인 극적 단일화
  • pgvector HNSW 도입 — 기존 Elasticsearch, Redis, MongoDB의 복잡한 이종 분산 데이터베이스 클러스터를 걷어내고, Neon PostgreSQL의 pgvector 확장 모듈의 HNSW 코사인 유사도 검색 인덱스 하나로 벡터 검색 흐름을 통합 구축하여 레이턴시 단축.
  • DB 기반 세션 관리로 Redis 대체 — 세션 정보 관리를 Redis 인메모리 스토리지 대신 Neon DB의 user_sessions 테이블로 통합 전환하여 데이터베이스 서빙 및 라이프사이클 비용 효율화.
⚙️ 경량 배치 & 비동기 파이프라인 리팩토링
  • GitHub Actions Cron 크롤러 — Apache Airflow, Spark, Kafka 클러스터를 전면 배제하고, Python 비동기 스크립트 기반 경량 크롤러로 대폭 다이어트하여 7일 주기 배치를 자동 트리거화.
  • Blue-Green Swap 무중단 데이터 교체 — 수집 후 24시간 격리 데이터베이스 검증 및 pgvector 인덱스 교체 기믹을 활용하여 1인 무중단 서비스 운영 기틀 정립.
  • 에러 상품 격리 및 핀포인트 복구 대시보드 구축 — 필수 메타 유실, 가격 전무, 임베딩 누락, 이미지 깨짐 등 4대 치명 오류가 감지된 상품을 자동 이관 대상에서 배제하여 Staging에 격리 유지하고, 관리자 에러 통제 탭에서 단일 핀포인트 실시간 [재수집] API(최저가 쇼핑 검색 5개 즉시 갱신 및 CLIP 연산) 및 벌크 복구 조치 바인딩을 신설하여 파이프라인의 안정성을 비약적으로 향상시킴.
📊 1인 임베디드 모니터링 시스템 구축
  • cgroups & psutil 통합 자원 감지 — 복잡한 메트릭 파이프라인 대신 FastAPI 라이프사이클 데몬에 임베디드 링버퍼(24h) 자원 감지기를 탑재하여 CPU/RAM 상태 상시 모니터링 및 Slack 자동 알림 경보망 구현.
Data Pipeline

시스템 파이프라인

1

GitHub Actions 배치 크롤링 — 7일 주기 자동 트리거

Render 무료 서버의 RAM 512MB 한계를 고려해 크롤링 연산을 GitHub Actions 환경으로 분리했습니다. Render 서버 부하 없이 독립 VM에서 6개 브랜드 수집이 실행됩니다.

2

크롤링 — 에잇세컨즈 · 탑텐 · 유니클로 · 스파오 · 지오다노 · 폴햄

상품명·이미지·가격·상세 정보를 수집해 Neon DB의 staging_products 테이블에 1차 격리 저장합니다. 수집과 동시에 Cloudinary staging/{brand} 폴더에 이미지를 업로드합니다.

3

임베딩 사전 추출 → DW DB 보관

수집 직후 HuggingFace Space의 YOLOv8 추론 서버에서 배경을 제거(Pre-Crop)하고, Fashion-CLIP 이미지 임베딩(512d)을 추출해 Neon DB product_embeddings 테이블에 사전 적재합니다.

4

24시간 격리 대기 → 에러 검증 및 Blue-Green Swap

수집 데이터에 대해 24시간 격리 유예를 거치며 정합성을 전수 검사합니다. 필수 메타 유실, 가격 전무, 임베딩 누락, 이미지 깨짐 등 4대 치명 에러가 감지된 상품들은 자동으로 스위칭 대상에서 제외(격리 배제)되어 Staging에 대기 보존됩니다. 정상 상품들만 운영 DB로 무중단 Swap(Blue-Green 기믹)되며, 격리된 에러 상품은 운영자가 어드민 "에러 상품 통제" 탭에서 실시간 핀포인트 재수집 및 임베딩 재생성 조치를 즉시 실행할 수 있습니다.

1

사용자 입력 — 이미지 / 텍스트 / 이미지+텍스트

메인 페이지에서 착용 사진·상품 이미지를 업로드하거나, 텍스트 키워드를 입력하거나, 두 가지를 함께 입력할 수 있습니다. 입력 유형에 따라 아래 세 가지 검색 경로 중 하나로 분기됩니다.

Pipeline

시스템 파이프라인

1

Airflow DAG 실행 — 매일 새벽 2시 자동 트리거

스케줄러가 DAG를 자동 실행해 크롤링 → 전처리 → 임베딩 전 과정을 무인 자동화로 처리합니다.

2

크롤링 — 유니클로 · ZARA · 탑텐 · 무신사 스탠다드 · 8-seconds

상품명·이미지·가격·상세 정보를 수집해 Hadoop에 원본 저장합니다. 탑텐은 상세 정보가 이미지이므로 OCR로 텍스트를 추출합니다.

3

Spark 전처리 — Hadoop Parquet 변환

병렬 처리로 데이터 정제·중복 제거·이미지 다운로드 후 Parquet 포맷으로 변환해 분석 효율을 높입니다.

4

PostgreSQL · MongoDB 분리 적재

정형 상품 데이터는 PostgreSQL(JSONB · 시계열 파티셔닝), 크롤링 원본·로그·AI 분석 결과는 MongoDB에 저장합니다.

5

Naver 쇼핑 API — 최저가 5개 수집

상품명으로 Naver API를 조회해 오름차순 최저가 5개 판매처를 수집합니다. MongoDB 캐시로 중복 API 호출을 방지합니다.
